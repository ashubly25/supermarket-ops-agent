# Recording script — 4–5 min walkthrough

Covers the §6 sequence in order: receive stock → multi-item bill with an edit → oversell guard →
khata cycle → PDF invoice → analysis deck → preference, `/new`, still remembered.

Every "expect" line below is what the deployed bot actually replies, computed from the seeded
catalogue. If a reply differs materially, stop and re-take — don't narrate around it.

---

## Before you hit record

```bash
# 1. Reset the demo chat so history and drafts are clean (keeps the catalogue).
#    Send this IN the chat, not the shell:
/new

# 2. Confirm the bot is up and on the current build.
ssh ubuntu@130.210.53.240 \
  'sudo docker compose -f supermarket-ops-agent/docker-compose.yml logs --tail 3'
#    Want: "Bot online as @zwigato_store_bot"
```

- **Nothing else may poll the bot.** No `npm run dev` anywhere, or replies go missing mid-take.
- Phone or desktop Telegram, one chat, full screen. Hide other chats — the sidebar is a distraction.
- Zoom the text up one notch. Reviewers watch this in a small window.
- Type slowly enough that the reply lands before you finish the next message. Steps take 3–8s.
- Have `~/Downloads` visible-ready for the PDF/PPTX opens at 3:10 and 3:50.

**Don't clear the catalogue.** The numbers below assume the seeded 19 SKUs.

## 0:00 — Frame it (spoken, no typing)

> "This is a kirana store run entirely from Telegram. No app, no forms — the shop owner just
> types. Behind it is a Vercel AI SDK agent with 34 tools over SQLite. Every business rule —
> GST, oversell, credit — is enforced in the tools, not the prompt."

Keep it under 20 seconds. Then start typing.

## 0:20 — Receive stock

```
50 packets of Maggi came in, cost ₹12, MRP ₹14
```

**Expect:** `Received 50 pkt Maggi Masala Noodles 70g @ ₹12 cost, MRP ₹14. Stock now 150 pkt.`

> Say: "It resolved 'Maggi' to the real SKU, took cost and MRP, and journalled the movement."

---

## 0:45 — Multi-item bill

```
make a bill: 2kg sugar, 1 aashirvaad atta, 4 maggi, 1 amul butter
```

**Expect:** a 4-line draft, total around **₹483**, GST shown inclusive, and a question about
payment mode.

> Say: "One message, four items. It's a draft — stock has not moved yet."

---

## 1:10 — Edit mid-build

```
drop the butter, make it 6 maggi
```

**Expect:** butter gone, Maggi at 6, total recalculated (**₹451**).

> Say: "The bill is state in SQLite, so it edits across turns. Stock still untouched."

---

## 1:35 — Oversell guard (the money shot)

```
add 200 maggi
```

**Expect:** a refusal naming the real number — `only 144 sellable in stock` (150 minus the 6
on this bill).

> Say: "That refusal comes from the tool, not the prompt — it can't be talked out of it.
> Note it also subtracts what this open draft already claims."

Then finalize:

```
cash, finalize
```

**Expect:** `Bill #1 finalized — ₹451.00 cash` and stock decremented **now**, not earlier.

---

## 2:05 — Khata cycle

```
put ₹500 on Ramesh's credit
```
**Expect:** `₹500 added to Ramesh's khata. Balance now ₹500.`

```
Ramesh paid ₹300
```
**Expect:** `Balance now ₹200.`

```
Ramesh's balance?
```
**Expect:** `Ramesh owes ₹200.`

> Say: "Khata is the credit ledger every kirana runs. Charge, part-payment, balance — and
> settling a customer who doesn't exist is refused at the tool layer."

---

## 2:45 — Daily close

```
today's sales?
```

**Expect:** bill count, sales total, tax collected, cash vs UPI split, top items.

> Say: "Tax collected is computed per slab, not a flat percentage."

## 3:05 — PDF invoice

```
send me that bill as a PDF
```

**Expect:** a confirmation naming the bill number, then a **PDF document arrives in the chat**.

**Open it on camera.** Point at: shop name + GSTIN header, per-line HSN and CGST/SGST,
the per-slab summary, total in words, round-off line.

> Say: "Generated by the agent's own pdfkit tool — not a screenshot, not text pretending
> to be a document. This is a GST-compliant tax invoice."

Give the PDF 8–10 seconds on screen. This is a graded deliverable; don't rush past it.

---

## 3:45 — Analysis deck

```
make this week's analysis deck
```

**Expect:** a confirmation, then a **.pptx arrives**.

**Open it.** Scroll the slides: title, sales summary, top items chart, payment-mix doughnut,
daily-trend line, GST-slab table, stock health, reorder plan, expiry watch.

> Say: "Real charts — native PowerPoint chart objects from the sales data, plus a
> velocity-based reorder plan and a FEFO expiry watch."

Another 10 seconds. Let them see actual charts.

```
always assume UPI unless I say cash
```
**Expect:** confirmation that it's remembered.

```
/new
```
**Expect:** `Fresh chat. Store data and your preferences are remembered.`

> Say: "New conversation — the message history is gone."

```
bill 3 maggi and finalize
```

**Expect:** finalized **via UPI without being asked** — the preference survived the reset.

> Say: "It never asked for payment mode. That preference lives in SQLite, outside the

## 4:50 — Close (spoken)

> "Stock, bills, credit and preferences are all durable. Two bills at once can't oversell —
> writes are serialised transactions and finalize re-checks inside the transaction."

## If something goes wrong mid-take

| Symptom | Do this |
|---|---|
| No reply for >20s | Wait. A multi-tool turn can take 15s. Don't double-send — you'll get two bills. |
| Reply mentions a rate-limit | Re-send the same message. Nothing was saved. |
| Bill numbers drift from this script | Fine — they're sequential per store, not per take. |
| Draft left open from a botched take | `show me the bill` then `cancel it`, or `/new` and start over. |

**Don't** re-send a `finalize` that appeared to fail — idempotency means the retry returns the
same bill, but on camera it reads as a double-charge.

## One thing to say out loud

If you type the brief's `new item: Amul Butter 100g, GST 12%`, the agent pushes back —
the 12% slab was abolished on 22 Sep 2025 (GST 2.0: 0/5/18/40). **That's deliberate**, and
README explains it. If you demo it, say so, or it looks like the agent ignoring an instruction.
Safest: leave it out of the recording and let the README make that argument.
